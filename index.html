EASY EARN — Admin
Black · White · Golden · PKR · Real API only, no demo data

The token is stored in sessionStorage only and is sent as Authorization: Bearer <token>. If an endpoint returns 404 or another error, the panel shows that error plainly instead of inventing data.

Admin login

Log in with an admin account. This panel checks user.role == admin on login, and verifies admin access when the server does not return a role. Non-admin accounts are refused here even if login itself succeeds.

First login? The backend seeds admin@shahearn.local with a default password printed in its startup log — change it immediately after first sign-in. Note: the shipped backend has no password-change endpoint, so see docs/DEPLOYMENT.md §11 for how to rotate it. Never share the admin token.

Add task

List: GET /api/admin/tasks (falls back to GET /api/tasks — the backend has no admin task-list route, so the fallback is the normal path) · Create: POST /api/admin/tasks (type must be survey, task or offerwall) · Update: PUT /api/admin/tasks/:id · Delete: DELETE /api/admin/tasks/:id (backend soft-removes: sets active = 0, keeping user-task history).

Reward configuration

Read: GET /api/config/public · Save: POST /api/admin/config. Only the keys above are accepted by the backend — any other key is rejected. Empty fields are left unchanged.

Withdrawals

        
Important: Approve ≠ paid. Approve only moves a request forward. Use Mark paid only after a real payout through JazzCash, Easypaisa or bank transfer, and enter the real payout reference — it is required. A withdrawal must never be marked paid without one. Rejection refunds coins server-side; this panel does not create a refund itself.

        

        
IDUserMethod / accountAmountStatusActions

        
Source: GET /api/admin/withdrawals · POST /api/admin/withdrawals/:id/approve · POST /api/admin/withdrawals/:id/mark-paid (body: {payout_reference}) · POST /api/admin/withdrawals/:id/reject (body: {reason}). Until a payment provider is integrated, withdrawals stay pending — see docs/DEPLOYMENT.md and docs/INTEGRATIONS.md.

Advertisements

        

        

        
IDUserNetwork / eventCoinsDate

        
Source: GET /api/admin/ads (returns {config, events, total_coins_awarded}) + GET /api/config/public (ad unit IDs). Note the backend's current ad mode: when ADMOB_SSV_KEY is unset, rewards are server-capped, fixed-amount and idempotent — the backend itself warns this is not production-safe for real AdMob payouts, so SSV must be set before launch (see docs/INTEGRATIONS.md). This panel has no way to add an ad network; that is a backend/app integration.

      

    


    

      

        
Fraud detection

        

        
IDUserReasonDetailsStatus

        

        
Source: GET /api/admin/fraud. To act on a flagged account, use the Users tab (flag/ban). Fraud rules themselves (duplicate devices, self-referrals, abnormal earn rates) are enforced server-side; this panel only displays what the backend flags.
